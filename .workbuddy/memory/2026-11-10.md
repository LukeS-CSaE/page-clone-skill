## page-clone-skill 定位调整：核心场景改为「抓取登录态页面」

用户澄清：本技能的核心用途是抓取**命令行无法黑箱获取的页面**（需登录），工作方式是配合人工登录后打开指定页面完成抓取。原 SKILL.md 第 18 行恰好写着"不要用于：抓取需要登录才能访问且用户未在浏览器中打开的页面"，与真实用途相反。

### 定位改写

- **SKILL.md description**：改为以登录态页面为主场景，补齐「抓取需要登录的页面」「复刻后台页面」「克隆当前打开的页面」等触发词
- **新增「为什么命令行方式不行」对比表**：登录态 / 渲染 / 可见性 / 交互门槛 四个维度对比 curl
- **执行流程前置「第 0 步（人工）：登录并打开目标页面」**，明确人工卡点
- **移除错误的「不要用于」限制**；新边界：批量爬站、代替用户登录、抓取未打开的页面
- 补充敏感数据提示（产物含登录后业务数据）、登录态不写入产物

### 关键技术事实（源码核对结论）

- `clone.js:147` 用 `--browserUrl http://127.0.0.1:PORT` → `BrowserManager.js:352` `connectOptions.browserURL` → puppeteer **connect**，attach 到既有浏览器实例，不另起实例 → 登录态/Cookie/渲染后 DOM 原样保留
- `list_pages`（`pages.js:11`）返回已连接浏览器的全部标签页，人工登录后打开的页会正常出现
- `evaluate_script` 支持 `pageId` 精确定位标签页（`script.js:72-80`，取决于 `pageIdRouting`）
- **`--url` 是已打开标签页的子串匹配，不是导航指令** —— 文档多处需明确此点
- **Chrome 136+ 起 `--remote-debugging-port` 在默认用户目录上被静默忽略**，必须配 `--user-data-dir` 指向非标准目录（Chrome 官方公告 developer.chrome.com/blog/remote-debugging-port）。副作用正好有利：独立 profile 可长期保留登录态，实现「登录一次、长期复用」
